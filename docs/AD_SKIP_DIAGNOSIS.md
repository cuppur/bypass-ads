## 无控件广告的视觉补查

此前多次节点采样只能读到小程序底层首页，画面中实际存在的“广告 ▾ | 跳过”和旁边倒计时没有对应的可操作无障碍节点。继续增加节点选择器无法解决这类 SDK / Canvas 出口。

- 新增随 APK 打包的中文文字识别模型 com.google.mlkit:text-recognition-chinese:16.0.1。模型在本机执行，不依赖运行时下载或联网识别。
- Android 11 及以上，已识别的微信 AppBrand / 支付宝 XRiver、Nebula 小程序前台，可以检查画面左上角。保守模式仅观察；激进和彻底疯狂模式可在严格证据满足时执行。设置页提供“小程序视觉补查”开关。
- 必须同时找到精确出口文字、独立广告标识、相邻短倒计时。右上角宿主退出胶囊、裸 X、普通关闭、支付或导航文字均不能借此通道获得点击权限。
- 点击位置来自实际 OCR 文字边界，不保存固定坐标。动作前再次取图，检查同一出口、倒计时未增加且至少剩余 2 秒、图像未过期和新鲜前台窗口未变化。
- 节点与视觉通道共用执行所有权，直到动作后验证结束。服务切换也共享此所有权；异常、取消、动作失败均释放，避免重复点击或锁死。
- 系统截图不可用、模型不可用、出口变化、页面切换、最后一秒、证据不足均不盲点。自然结束时间附近的消失不能确认为自动跳过。
- 验证使用连续两次新鲜画面、原出口区域广告证据消失和像素变化。进入浏览器、应用商店或桌面时记录疑似误点并停止。
- HyperOS 更新后可能省略 onServiceConnected；真实无障碍事件也会初始化引擎及视觉任务，不能只让界面显示服务已绑定。
- 正式版 R8 曾移除 ML Kit 清单反射发现的注册组件无参构造方法，引发 NoSuchMethodException，使模型不可用。已显式保留这些构造方法，并加入按实际 Release 清单及 R8 mapping 检查的打包关卡。初始化失败时，清理阶段只关闭已经成功创建的客户端，避免重新初始化异常导致整个 App 崩溃。

识别只向模型提供左上角裁剪图。图像、原始 OCR 页面文字和区域像素样本只留在内存，检查后释放；黑匣子只记录固定出口标签、边界、信号数量、状态代码和动作结果。正式清单没有 INTERNET 权限。临时真机诊断截图不属于应用记录或导出内容。

官方模型说明：[ML Kit 中文文字识别 Android 文档](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)。截图接口见 [Android AccessibilityService 文档](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)。

## 节点规则与执行链补强

- 分类器统一识别文字、无障碍描述、资源 ID、驼峰 ID、独立倒计时及直接叶子的跳过语义。成熟应用专用规则可以使用精确 ID 或无文字出口，保留专用来源边界，不能伪装成全局跳过文字。
- 广告规则的 matchTime 不再让明确语义出口在进入后 10 秒失效。进入后立即匹配；短时主动轮询与识别生效时间不同。小程序前台单条补查任务覆盖 SDK 无事件及晚出现广告。
- 每次广告查询共用新鲜完整窗口根节点，避免倒计时 CONTENT_CHANGED 只给出计时 TextView，而关闭按钮位于兄弟节点的问题。
- 关闭和旁边独立倒计时支持小型、可检查、边界内可见的控件布局。普通宿主关闭按钮仍需要当前广告证据；右上角固定退出控件明确排除。
- QQ 音乐增加文字、描述、SDK ID、可点击父节点及中心手势补强。真正返回前台时重新建立广告上下文；同一进程、同一 Activity 的后续广告也可处理。
- 广告确认退出后重新准备同组规则次数；保留冷却和前置条件。一条广告共用有限动作预算，未生效动作只在新鲜状态复查和预算允许时重试。
- 同一 Activity 的重复窗口通知、名称从空补全不会反复重置延迟、次数或上下文。2.2 秒等待期间每 300 ms 通知的设备场景覆盖了这个问题。
- 运行状态在创建、连接、销毁、系统授权变化及页面恢复时同步读取当前身份所有者；首页、无障碍开关和后台保护共用该状态，手动补记也直接检查当前实例。已授权但暂未连接的服务显示“正在恢复”，无需再次声称首次授权；缺少直接控制权限时恢复开关仍提供授权入口。最终在真实屏幕上验证服务关闭时“需要授权”，开启后首页及无障碍开关“正常运行”、后台保护“良好”。同一首页的 USB 控件 dump 曾返回与实际画面不一致的过时文字，换新输出文件仍未消除差异；不能据此独立断言实际屏幕异常，本项结论以画面和当前实例日志交叉确认。
- 无编号规则的验证身份包含实际索引、应用/全局组身份及动作区域，避免编号碰撞。系统接受动作与广告确实关闭分别记录。
- 生成器规范化单条字符串、单对象和数组简写，检查所有生产选择器、策略元数据及编号；合并同名上游组时保存各规则自己的页面范围。

公开规则参考：[李跳跳自定义规则项目](https://github.com/Game-Challenge/LiTiaoTiao)、[Lin-arm 微信规则](https://github.com/Lin-arm/GKD_subscription/blob/main/src/apps/com.tencent.mm.ts)、[Lin-arm 支付宝规则](https://github.com/Lin-arm/GKD_subscription/blob/main/src/apps/com.eg.android.AlipayGphone.ts)、[AIsouler 微信规则](https://github.com/AIsouler/GKD_subscription/blob/main/src/apps/com.tencent.mm.ts)。参考公开定位、SDK 就绪等待和布局变化触发思路；未复制软件实现或整套规则正文。独立“星星充电”App 的规则不代表其小程序。

## 记录黑匣子

- 一条广告对应一条会话，多个候选及重试不会增加广告数量。连续同页广告在稳定退出后开始新会话。
- 记录广告证据、匹配来源、候选、执行条件、延迟等待、动作接受情况、实际尝试次数、新鲜状态验证及最终原因。关键阶段与最近事件共同保留，倒计时事件不能挤掉动作与验证。
- “已跳过 / 未成功 / 待诊断”可筛选；未成功应用列出数量，并可进入该应用的记录。没有广告证据的普通页面不会被当成漏跳计数。
- 无法自动发现广告时可以手动补记一次漏跳，附上最近一次完整页面和视觉通道的非内容诊断。
- 详情把状态代码解释成中文，支持导出。保留最近 7 天、最多 2000 条会话，界面加载最新 500 条；动作结果未确认会明确显示。
